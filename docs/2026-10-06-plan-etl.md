# Plan — K-B en ETL explicite (2026-10-06)

Statut : **validé par Sabine le 2026-10-06**, avec les deux recommandations ci-dessous (renommer après W0 ; ce plan avant W0). Les estimations sont de Claude et n'ont pas été relues.
Les citations `fichier:ligne` sont relevées sur `main` (`9544a23`) et ont été recontrôlées par un
second passage indépendant.

## La cible (donnée par Sabine)

- E, T et L sont faits de fonctions génériques. Aucun module générique n'importe une source par son
  nom.
- Un module par source porte ce qui lui est propre : télécharger (E), lire le brut et le convertir
  en `Item` (T).
- L reste générique.
- Chaque source est déclarée **une seule fois**.
- La partie générique de T sait lire un dossier de pages (TLDR).

## Ce qui est

- **Deux déclarations des sources.** `SOURCES` dans `collect.py:45-57` (instances à collecter) et
  `list_readers_by_source` dans `raw_items.py:113-138` (un `match` sur la classe de chaque
  instance). Ajouter une source touche 5 endroits (revue, G2).
- **Les modules génériques importent les sources par leur nom.** `collect.py:9-21` (6 classes et
  les listes suivies), `raw_items.py:13-31` (lecteurs, classes, `convert_*`), `items.py:17-21`
  (5 `dataclass`).
- **Le modèle commun connaît chaque source.** `items.py:69-145` porte les 5 `convert_*`.
- **La lecture dépend de la collecte.** `raw_items.py:17` importe `collect.SOURCES`. Un dossier brut
  d'une source qui n'est plus suivie est sauté (`raw_items.py:65-68`, #87).
- **Du code de source dans le module générique de T.** Les adaptateurs de `raw_items.py` fixent
  `last_collected_at=None` pour CISA (`raw_items.py:123`) et `expected_size=RANKING_SIZE` pour le
  classement (`raw_items.py:135`).
- **Le lecteur des releases dépend de l'instance.** `read_releases(raw_response, repository)`
  (`github_releases.py:26`) reçoit le dépôt de la source suivie, à l'import (`raw_items.py:126-130`)
  comme à la collecte (`github_releases_source.py:32`). Le brut le contient pourtant : `html_url`
  vaut `https://github.com/<owner>/<name>/releases/tag/…` (`tests/fixtures/github_releases_extract.json`).
- **Un dossier de pages est sauté.** `raw_items.py:73-78` journalise « folder of pages without a
  reader » et passe au suivant. Seul TLDR écrit des dossiers de pages (`collect.py:113-119`).
- **Deux fichiers par source.** `x.py` (lecture) et `x_source.py` (téléchargement), à plat avec les
  modules génériques : 23 modules dans `src/k_b/`, plus `__init__.py`.
- **Une source en importe une autre.** `github_advisories.py:8` importe `CVE_ID` de `cisa_kev`.

## Le contrat

Trois types, dans un nouveau module générique `source.py` :

```python
class Source(Protocol):              # E : déplacé tel quel de collect.py:30-42
    name: str                        # le nom de son dossier brut
    extension: str
    def fetch(self, last_collected_at: datetime | None) -> bytes | dict[str, bytes] | None: ...

class SourceReader(NamedTuple):      # T : déplacé tel quel de raw_items.py:39-43
    read_entries: Callable[[bytes], Sequence[object]]
    convert: Callable[[Any, datetime, str], Item]

class SourceKind(NamedTuple):        # la déclaration d'une source, une seule fois
    folder_prefix: str               # "github_releases" lit github_releases_anthropics_claude_code/
    sources: tuple[Source, ...]      # E : les instances à collecter
    reader: SourceReader | None      # T : None tant que le lecteur n'existe pas (TLDR avant #57)
```

Un prototype de ces types, avec les instances réelles et `reader=None`, passe `mypy --strict`
(second passage).

- **Le lecteur est par sorte de source**, pas par instance : il est retrouvé par le nom du dossier
  brut, que la source soit encore suivie ou non (#87).
- **Un dossier appartient à la sorte** dont le préfixe est son nom entier, ou son début suivi de
  `_`. Un dossier qui ne correspond à aucune sorte est journalisé et sauté, comme aujourd'hui
  (`raw_items.py:67`).
- **Le préfixe est écrit une fois** : une constante `FOLDER_PREFIX` dans chaque module de source,
  qui sert au nom de ses instances (aujourd'hui en dur : `github_releases_source.py:24`,
  `github_advisories_source.py:25`, `tldr_source.py:31`) et à sa `SourceKind`.
- **Chaque module de source expose un `read_entries(raw: bytes)` à un seul argument.** Les
  adaptateurs de CISA et du classement quittent `raw_items.py` pour leur module.

La seule déclaration : `SOURCE_KINDS`, dans un module dédié `source_kinds.py`, une ligne par source.
Seul `cli.py` l'importe ; il la passe en paramètre à E (`collect_all_sources`) et à T
(`read_raw_items`), comme `collect_all_sources` reçoit déjà ses sources (`collect.py:66-67`). L'ordre
des sortes reprend l'ordre de collecte d'aujourd'hui (CISA, releases, alertes, classement, arXiv,
TLDR), dont dépendent les sorties de `test_cli.py`.

## L'arborescence visée

```
src/k_b/
  cli.py              compose : lit SOURCE_KINDS, appelle E, T, L
  source_kinds.py     SOURCE_KINDS : la seule déclaration des sources
  source.py           le contrat (Source, SourceReader, SourceKind)
  collect.py          E générique : appelle fetch, écrit le brut
  raw_store.py        E : écriture du brut, état de collecte
  http_download.py    E : téléchargement borné (#86 y passe à httpx)
  user_agent.py       E
  items.py            Item, ses types, et le motif CVE commun
  raw_items.py        T générique : brut (fichier ou dossier de pages) → items, rejets tracés
  merge.py            T générique : normalisation, doublons
  import_items.py     L : écriture de la base et du journal d'import
  database/           L : schéma
  sources/
    __init__.py       vide
    arxiv.py          arxiv_source.py + arxiv_papers.py + convert_paper
    cisa_kev.py       cisa_kev_source.py + cisa_kev.py + convert_vulnerability
    github_releases.py, github_advisories.py, github_most_starred.py   (même regroupement)
    github_api.py, github_dates.py, tracked_repositories.py            (communs aux sources GitHub)
    tldr.py           tldr_source.py ; son lecteur arrive avec #57
```

Les dépendances vont dans un sens : `cli` → `source_kinds` → `sources/*` → modules génériques. Deux
tests le gardent : aucun module générique n'importe `k_b.sources` ni `k_b.source_kinds`, et aucun
module de `sources/` n'importe `k_b.source_kinds`.

## Ce que devient chaque module

| `import_items.py` | Reçoit `SOURCE_KINDS` et le passe à `read_raw_items`. Rien d'autre : W0 le réécrit. |

## Les étapes

Chacune est une PR, et chacune laisse `uv run pytest`, ruff et `mypy --strict` verts.

**Étape 1 — Chaque conversion à côté de son lecteur** (≈ 45 min). Les 5 `convert_*` quittent
`items.py` pour `arxiv_papers.py`, `cisa_kev.py`, `github_releases.py`, `github_advisories.py`
et `github_most_starred.py`. Le motif `CVE_ID` passe de `cisa_kev.py` à `items.py` :
`github_advisories.py` n'importe plus une autre source. Dans le même commit, `items.py` cesse
d'importer les sources, sinon l'import tourne en rond. À toucher aussi : `raw_items.py:24-31`, qui
importe les `convert_*`, et `tests/test_items.py:9-21`, dont les tests de conversion partent vers
les tests des lecteurs (le test `SEED_SOURCES` reste). Déplacement pur : aucun comportement ne
change.

**Étape 2 — Le lecteur des releases tire le dépôt du brut** (≈ 45 min). `read_releases(raw)` sans
paramètre. Le dépôt est lu dans `html_url` par un motif ancré,
`^https://github\.com/([A-Za-z0-9_.-]+)/([A-Za-z0-9_.-]+)/releases/`, qui refuse aussi `.` et `..`
pour le propriétaire comme pour le nom. Ce contrôle vit à un seul endroit ; `GithubReleasesSource`
le réutilise (`github_releases_source.py:14`, `21`).
- **Erreurs.** Une release dont l'URL ne donne pas de dépôt est refusée, avec l'URL observée. Comme
  aujourd'hui, cela refuse tout le fichier (`raw_items.py:90`) : le refus entrée par entrée reste
  à G1, #61.
- **Contrôle à la collecte.** `fetch` (`github_releases_source.py:32`) compare le dépôt lu à celui
  suivi, sans tenir compte de la casse, et refuse sinon : défense en profondeur.
- **Changement de comportement.** Le titre de l'item (`items.py:108`) prend le dépôt écrit par
  GitHub, et plus celui de `TRACKED_REPOSITORIES`. Non vérifié sur les 4 dépôts suivis.
- **Tests.** D'abord : le brut d'un dépôt non suivi est lu. Puis les 4 appels
  `read_releases(..., REPOSITORY)` de `tests/test_github_releases.py` sont adaptés.

**Étape 3 — Le contrat et la déclaration unique** (≈ 2 h 45). `source.py`, `source_kinds.py`, une
constante `FOLDER_PREFIX` et un `read_entries` à un argument par module de source. `raw_items.py`
et `import_items.py` reçoivent `SOURCE_KINDS` ; `raw_items.py` n'importe plus `collect.py`.
- **Nouveaux tests, écrits d'abord.**
  - Un dossier `github_releases_<dépôt non suivi>/` est lu, puis un dossier
    `github_advisories_<écosystème non suivi>/` (premier cas de #87).
  - Chaque nom de source correspond au préfixe de sa sorte et d'aucune autre. Aucun préfixe n'est
    égal à un autre, ni le début d'un autre suivi de `_`.
  - Les deux tests de dépendances ci-dessus, sur une liste explicite des modules génériques, tant
    qu'ils sont à plat.
- **Tests à adapter.**
  - Les 5 imports `from k_b.collect import SOURCES` : `test_arxiv_source.py`,
    `test_github_most_starred_source.py`, `test_tldr_source.py`,
    `test_github_advisories_source.py`, `test_github_releases_source.py`.
  - Les 5 `monkeypatch.setattr(cli, "SOURCES", …)` de `test_cli.py`.
  - Les 9 appels `read_raw_items(` de `test_raw_items.py` et les appels `import_items(` de
    `test_import_items.py`.

**Étape 4 — Un module par source, dans `sources/`** (≈ 2 h 15). `git mv` des 13 modules de source,
puis fusion des 6 paires. `__init__.py` vide. Les tests suivent : `tests/sources/test_<source>.py`
(environ 19 fichiers), avec les cibles de leurs `monkeypatch.setattr(<module>, …)`. Le test de
dépendances passe de la liste explicite au paquet. Déplacement pur. Les docs qui citent les anciens
chemins sont mises à jour : `grep -rl` en trouve de 1 à 4 par module dans `docs/` et le `README.md`,
hors `docs/journaling/`, qui est daté.

**Étape 5 — T lit un dossier de pages** (≈ 1 h). Un dossier `<source>/<collecte>/` est lu page par
page : la date vient du nom du dossier, `raw_file_path` est le chemin de la page. Testé avec une
sorte factice. Cas de test :
- un dossier de pages lu ;
- un fichier caché dans le dossier, sauté ;
- un sous-dossier dans le dossier, journalisé et sauté ;
- un dossier dont le nom n'est pas une date de collecte, rejeté entier, comme un fichier.

`test_raw_items.py:116` (« source without reader and page folders are skipped ») est réécrit. TLDR
reste sauté, journalisé « source without a reader », jusqu'à #57.

## Options écartées

- **Le lecteur porté par l'instance de la source** (une méthode `read_entries` sur la classe). Il
  faudrait une instance pour lire, donc la liste des sources suivies : un dossier d'une source
  retirée ne serait plus lu (#87). C'est la conclusion de la revue (G2, G3).
- **`SOURCE_KINDS` dans `sources/__init__.py`.** Tout import d'un module de source, par exemple
  `k_b.sources.github_api` dans son test, chargerait toutes les sources et construirait leurs
  instances. Et une source qui importerait `k_b.sources` trouverait un paquet à moitié chargé
  (`ImportError`). Un module dédié, importé par `cli.py` seul, évite les deux.
- **La découverte automatique des sources** (parcours de `sources/` par `pkgutil`, points d'entrée,
  décorateur qui enregistre à l'import). Implicite, et la liste des sources n'est plus lisible à un
  endroit. La cible demande un ETL explicite.
- **Une classe de base abstraite** au lieu du `Protocol` : aucun code n'est commun aux sources. Le
  `Protocol` existe déjà (`collect.py:30`).
- **Garder deux fichiers par source** (`x.py`, `x_source.py`) : la cible demande un module par
  source. Le module fusionné le plus long, arXiv, ferait environ 220 lignes (`wc -l` :
  124 + 81, plus `convert_paper`).
- **Un sous-paquet `pipeline/` pour les modules génériques** : une fois les sources dans
  `sources/`, il resterait 11 modules à plat (avec `source.py` et `source_kinds.py`), plus
  `__init__.py`. Le déplacement n'apporte rien de plus.
- **Séparer dès maintenant T et L** (`import_items.py` lit et fusionne avant d'écrire) : W0
  réécrit ce module ; le faire avant serait le faire deux fois.
